# Panacea Vertical Computational Human Doctrine

**Status:** canonical mandatory repository doctrine  
**Owner direction:** 2026-09-27  
**Applies to:** every present and future agent/model, all three superpages, biomedical domains, simulation engines, knowledge/data layers, and every 2D/3D/3DCG representation.

This doctrine extends `PANACEA_COMPUTATIONAL_HUMAN_PLATFORM.md`. It does not authorize destructive rewrites of validated capability. It defines how Panacea must deepen vertically from the whole person to tissue, cell, organelle, molecular machinery, RNA, chromatin and DNA without leaving hidden biological gaps.

## 1. Strategic law — vertical depth before horizontal breadth

Panacea must not mature primarily by accumulating more pages, widgets, cards, organ panels or disconnected features.

The target is one shared **Computational Human Graph** projected through three primary superpages:

1. **Clinical Intelligence / AI-EMR** — observed patient truth, phenotype, longitudinal state, disease mechanism, evidence and intervention context.
2. **Body Exposure** — spatial biological projection from whole body to system, organ, tissue, microarchitecture, cell, organelle, molecular complex, RNA, chromatin and DNA.
3. **Simulation / Training** — executable mechanistic perturbation, intervention, procedure/device and counterfactual projection over the same shared state.

These are three lenses over one canonical biological architecture, not three separate biological databases.

## 1A. Depth compounding — breadth discovers, depth compounds

Horizontal breadth is useful for **discovery**, but it is not evidence of maturity. Ideas, candidate domains and future capabilities may be explored broadly, but implementation progress must preferentially compound inside a selected vertical slice until it reaches a defensible stopping boundary.

Canonical execution loop:

```text
EXPLORE BROADLY
-> SELECT ONE HIGH-VALUE VERTICAL SLICE
-> COMMIT TO THE SLICE
-> DEEPEN MECHANISM / STATE / INFRASTRUCTURE
-> INTEGRATE WITH THE SHARED HUMAN MODEL
-> TEST AGAINST REALITY
-> REFINE FROM ERROR / FEEDBACK
-> EXPAND BREADTH ONLY WHEN JUSTIFIED
```

Use the internal heuristic:

[
S_{compounding}
=
S_{vertical}
\times
D_{continuity}
\times
D_{reality}
\times
D_{feedback}
]

where:
- (S_{vertical}) = the existing domain × model × infrastructure × integration × validation depth;
- (D_{continuity}) = whether the capability is developed as a persistent longitudinal system rather than a one-off snapshot;
- (D_{reality}) = whether claims are confronted with real inputs, reference data, benchmarks, workflows, devices, failure cases or qualified human validation as appropriate;
- (D_{feedback}) = whether observed error/outcomes change the next model, implementation or calibration step.

This is an architecture and prioritization heuristic, never a clinical score.

Operational laws:
- **Breadth is a discovery queue; depth is the default execution lane.**
- Do not open several shallow implementation fronts when one existing high-value slice is still hollow.
- A slice is not deep because it contains more text, labels, routes, screens, meshes, model calls or commits.
- Prefer causal/mechanistic resolution, shared state, persistence, cross-system coupling, provenance, uncertainty, validation and outcome feedback over surface-area growth.
- Continue a selected slice until it is either materially mature for its declared scope or blocked by a concrete external dependency that software cannot resolve; record that boundary explicitly.
- Reality-testing must expose disagreement between prediction/model and observation. Never polish away error, unknown state or unsupported resolution.
- Refinement should follow measured failure, benchmark evidence, user/workflow friction, scientific falsification or validation results rather than novelty pressure.
- Once a reusable deep primitive exists, project it horizontally into additional organs/workflows/surfaces instead of rebuilding shallow copies.

The same rule applies recursively: whole human -> system -> organ -> tissue -> cell -> molecule, and input -> state -> engine -> coupling -> validation -> projection -> outcome. Depth must compound across both biological scale and software execution.

## 1B. Meaningful expansion and adaptive explanatory scale

The approved [Invictus Human Reality Principle](docs/superpowers/specs/2026-09-28-invictus-human-reality-principle-design.md) extends depth-over-dispersion with a second rule: Panacea may expand horizontally when the expansion materially increases the meaning, explanatory power or future capability of the **same Human Reality Model**.

### Meaningful horizontal expansion

A new domain, surface or modality is preferred when it strengthens several of the following at once:

- human-life relevance or user-authored goals;
- canonical-state reuse;
- longitudinal continuity;
- causal/mechanistic integration;
- cross-system coupling;
- reality feedback;
- validation potential;
- future-model/sensor absorbability.

Horizontal expansion must not create another independent human, duplicate state authority or a disconnected feature island.

### Adaptive explanatory scale

Panacea should reason and render at the deepest scale that is relevant to the current human question and scientifically supportable. Depending on the problem, the explanatory path may extend outward or inward:

```text
world / environment
-> human
-> system
-> organ
-> tissue
-> microarchitecture
-> cell
-> organelle
-> molecular complex / pathway
-> RNA / gene / epigenetic layer
```

This does not require maximal resolution everywhere. Future runtimes may allocate greater computational resolution around the system, event or scale that currently matters while leaving stable regions coarse.

A future capability may be designed before current technology can execute it, but unsupported intermediate biology remains **VERTICAL GAP — NOT YET MODELED**. Future ambition never authorizes a fabricated bridge.

Human meaning guides which questions deserve deeper investment; it does not change biological evidence, causal certainty or truth class.

## 2. Hard prohibitions

The following are **forbidden design patterns** for all future work.

### 2.1 Superficial
Do not call a capability deep, mature or complete merely because it has:
- polished UI;
- many labels;
- many 3D meshes;
- cinematic animation;
- long explanatory text;
- large route/component counts;
- shallow organ summaries;
- static pathway diagrams.

Depth requires connected biological mechanism and explicit cross-scale state.

### 2.2 Artificial / fabricated
Do not invent:
- patient-specific anatomy or physiology that was not measured/inferred by an explicit model;
- molecular states, pathway activity, receptor occupancy or omics values without source/model basis;
- decorative molecular structures presented as real;
- synthetic physiological responses presented as observed;
- equations, constants, parameters or causal links without evidence/provenance;
- fake “clinical realism” for visual effect.

A scientifically unknown value must remain unknown. A simulated value must remain simulated.

### 2.3 Subjective / unsupported
Do not encode personal taste, arbitrary biological ranking or untraceable expert-sounding opinion as truth.

Claims about structure, physiology, pathology, mechanism, intervention effect or model fidelity must be:
- evidence-backed;
- provenance-linked;
- versioned when appropriate;
- explicit about assumptions;
- explicit about supported population;
- explicit about uncertainty;
- explicit about validation class.

When evidence is disputed or heterogeneous, represent the disagreement rather than selecting a preferred story without justification.

## 3. No Hollow Gap Principle

For every biological entity claimed as mature, Panacea must expose a traceable path through every scientifically relevant intermediate scale:

```text
person
-> body region
-> organ system
-> organ
-> anatomical subdivision
-> tissue
-> microarchitecture / functional unit
-> cellular niche
-> cell type
-> cell state
-> membrane / organelle
-> macromolecular complex
-> protein / post-translational state
-> signaling / regulatory pathway
-> metabolite / ion / electrochemical state
-> RNA / transcript / splice isoform
-> gene / regulatory element
-> chromatin / epigenetic state
-> DNA / genomic variation
```

Where evidence permits, the reverse causal path must also be representable:

```text
genomic / epigenomic perturbation
-> transcript change
-> protein / pathway change
-> cellular phenotype
-> tissue phenotype
-> organ dysfunction
-> system response
-> whole-person phenotype
```

A relevant but missing layer must be explicitly labeled:

**VERTICAL GAP — NOT YET MODELED**

A biologically inapplicable layer may be labeled **NOT APPLICABLE** with rationale.

Never hide a missing middle layer behind gross-anatomy detail, genomics, animation, content volume or visual polish.

## 4. Deepest scientifically supportable representation

“Deep” means the deepest level that can be represented with evidence, explicit assumptions and an appropriate computational or semantic model.

Agents should keep drilling down until one of these boundaries is reached:
- the biological relationship becomes scientifically inapplicable;
- evidence is insufficient;
- no defensible model exists;
- required parameters are unavailable;
- the remaining layer would be decorative rather than mechanistic.

At that boundary, record the gap and evidence need. Do not fabricate a bridge.

## 7. Cellular and molecular continuity

Every mature organ/tissue domain must connect, where biologically applicable, to:
- membrane transport and electrophysiology;
- cytoskeleton and mechanotransduction;
- mitochondria, oxidative phosphorylation and metabolic flux;
- ER/Golgi protein processing;
- lysosome/autophagy;

Shared pathway engines should be reused rather than duplicated per page.

## 8. Hidden-state truth classification

Panacea may model biological variables that are not directly observable in a specific person, but it must not present them as measurements.

Every state must carry one of these classes or a stricter compatible taxonomy:

1. **Observed** — measured/imported/clinician-authored patient truth.
2. **Derived** — deterministic transformation of observed inputs.
3. **Estimated latent state** — probabilistic inference conditioned on observations/model.
4. **Simulated** — model-generated state under explicit assumptions.
5. **Population/reference prior** — literature/reference population context, not patient truth.
6. **Unknown** — insufficient evidence/data.

For latent state estimation:

[
p(\mathbf x_t\mid \mathbf y_{1:t},\mathbf u_{1:t},\mathbf e_{1:t})
]

must conceptually remain distinct from observed truth.

Unknown uncertainty must remain unknown; do not manufacture precision.

## 9. 3DCG / visualization must be vertically deep

Visualization is part of the scientific model, not decoration.

### 9.1 Required continuity
Where biologically applicable, the user should be able to move continuously through:

```text
whole body
-> system
-> organ
-> compartment
-> tissue
-> histological unit
-> cellular niche
-> cell
-> membrane / organelle
-> molecular complex
-> pathway
-> protein
-> RNA
-> chromatin
-> DNA
```

Transitions may use LOD, cross-fade, sectional views, exploded views, volumetric views or linked scientific representations, but they must preserve biological parent/child identity and provenance.

### 9.2 No superficial 3D
Forbidden:
- generic organ meshes presented as “digital twin”;
- decorative particles presented as molecules/cells;
- arbitrary glow/heat maps without mapped variables;
- scripted animation presented as physiological simulation;
- fake histology generated only for appearance;
- fabricated anatomy to fill missing source geometry;
- molecular structures invented for cinematic effect.

If a high-fidelity representation is unavailable, display the validated lower-fidelity representation and mark the missing layer.

### 9.3 Geometry + state + evidence
The intended rendering contract is:

[
R_t = \mathcal R(G,\mathbf x_t,P,L,C,E)
]

where:
- (G) = validated/reference geometry;
- (mathbf x_t) = physiological/model state;
- (P) = pathology/intervention state;
- (L) = biological scale/layer;
- (C) = camera/visual context;
- (E) = evidence/provenance metadata.

State changes should drive visual changes whenever a mechanistic mapping exists. Visual effects must not manufacture state.

### 9.4 Scientific fidelity before spectacle
At microscopic/molecular scale, “high-end” means scientifically faithful, not merely photorealistic. Prefer validated structural/scientific representation to visually impressive but invented geometry.

## 10. Cross-scale pathology

Pathology must traverse the same graph.

A disease or lesion should be able to connect:
- initiating cause/risk;
- molecular pathway;
- cell injury/state transition;
- tissue-level morphology;
- organ dysfunction;
- compensatory physiology;
- systemic phenotype;
- imaging/lab/clinical manifestation;
- intervention targets;
- response/remodeling.

Do not implement a disease as a detached card if its mechanism can be represented in the shared graph.

## 11. Mechanistic simulation depth

Simulation technique should match biological scale rather than forcing one method everywhere.

Examples:
- whole body: coupled ODE/DAE, control systems, state estimation;
- organ/system: compartmental/network models;
- organ mechanics/flow: FEM/CFD/electrophysiology where justified;
- tissue: continuum/reaction-diffusion;
- cell populations: agent-based where justified;
- single cell: electrophysiology/ODE/DAE;
- signaling: kinetic reaction networks;
- metabolism: kinetic/constraint-based models;
- gene regulation: GRN/stochastic models;
- molecular interaction: kinetic/statistical/structural models when justified.

Use advanced compute (GPU/WebGPU/HPC/MD/FSI/neural operators) only when workload, validation, benchmark and rollback justify it.

## 12. Vertical completeness and hollow-gap gates

For entity (E), define a weighted vertical completeness heuristic:

[
VC(E)=
\frac{\sum_i w_i C_i}{\sum_i w_i}
]

and a hollow-gap floor:

[
HG(E)=\min_i C_i
]

where (C_i\in[0,1]) is completeness of each scientifically relevant scale.

These are prioritization heuristics, not clinical metrics.

A capability must not be called vertically mature if a critical intermediate layer has near-zero coverage even when its top and bottom layers are excellent.

Unknown completeness must remain unknown; do not fabricate percentages.

## 13. Agent task-selection law

When no narrower owner instruction overrides it:

1. preserve safety, security, privacy, provenance and existing validated work;
2. inspect current main and existing canonical primitives;
3. find the deepest scientifically meaningful unresolved vertical gap;
4. deepen the existing biological entity before creating parallel horizontal breadth;
5. connect anatomy -> physiology -> pathology -> cell -> molecular/genomic layers where applicable;
6. strengthen cross-scale/cross-system coupling;
7. add executable models only with explicit equations/algorithms, units, assumptions and evidence;
8. strengthen uncertainty, provenance and validation;
9. project the resulting shared state into the three superpages;
10. optimize performance/UX only after the scientific structure is sound.

A new superficial feature should lose priority to a deeper evidence-backed vertical slice.

## 14. Definition of vertical done

A biological entity is not vertically done because its page works.

For the intended scope, verify:
- parent/child anatomical hierarchy;
- tissue/microarchitecture mapping;
- cell type/niche mapping;
- applicable organelle/molecular pathway mapping;
- applicable transcript/gene/regulatory mapping;
- physiology and pathophysiology mechanisms;
- cross-system coupling;
- truth class for every patient-linked state;
- uncertainty/provenance;
- explicit unknowns and unsupported regions;
- visualization fidelity at every implemented scale;
- executable simulation contract when simulation is claimed;
- validation class and reproducible tests.

If a relevant layer is missing, the entity remains vertically incomplete.

## 15. Canonical design maxim

**Do not make Panacea look deeper than it is. Make Panacea become deeper than it looks.**

Evidence > spectacle.  
Mechanism > description.  
Continuity > feature count.  
Explicit unknown > fabricated certainty.  
Vertical depth > horizontal breadth.

## 16. Longitudinal domino-effect operating law

Panacea must not represent physiology as a bag of simultaneous snapshots. Every running biological engine must participate in an ordered, time-aware, causally linked state transition system.

For the coupled state:

[
\mathbf X_{t+\Delta t}
=
\Phi(
\mathbf X_t,
\mathbf U_t,
\mathbf E_t,
\boldsymbol\theta,
\mathbf C_t,
\Delta t
)
]

where `C_t` explicitly represents cross-system coupling, feedback and compensatory relationships.

A change in one subsystem should propagate only through explicit validated dependency edges. The intended pattern is:

```text
perturbation
-> primary local response
-> downstream organ/system effect
-> compensatory response
-> secondary consequence
-> counter-regulation / adaptation
-> new longitudinal equilibrium or decompensation
```

Required properties:

- **Sequential:** event ordering, causal precedence and time constants are explicit.
- **Simultaneous where biologically required:** independently active systems may evolve concurrently under the same scheduler.
- **Longitudinal:** prior state constrains subsequent state; history cannot be discarded when biology is path-dependent.
- **Domino-linked:** cross-system effects propagate through typed mechanistic dependencies rather than page-to-page callbacks.
- **Balanced:** mass, charge, volume, energy or other conserved quantities must respect relevant invariants when the model class supports them.
- **Compensated:** homeostatic and counter-regulatory responses must be represented where evidence supports them.
- **Related:** every transition must preserve links to the contributing states, mechanisms, parameters and provenance.
- **Reversible/auditable:** the path from output back to upstream evidence/model parents must remain inspectable.

Examples include:
- hemorrhage -> reduced preload -> reduced stroke volume -> sympathetic activation -> vasoconstriction/tachycardia -> renal sodium/water retention;
- hypoventilation -> PaCO2 rise -> acid-base shift -> chemoreceptor response -> ventilatory compensation;
- reduced renal perfusion -> renin release -> angiotensin II/aldosterone -> vascular/volume response -> altered cardiac loading;
- infection -> innate immune activation -> cytokine signaling -> endothelial/hemodynamic effects -> neuroendocrine stress response -> metabolic adaptation.

No compensatory response may be invented merely to make a trajectory look “realistic”. If a feedback loop is not yet modeled, declare the missing coupling explicitly.

## 17. Operating-system synchronization contract

All superpages and engines must consume the same longitudinal state graph and must not maintain conflicting biological timelines.

The system should converge toward a single event/state fabric with:
- canonical timestamped state transitions;
- deterministic or explicitly stochastic scheduling;
- dependency-aware engine execution;
- explicit feedback/counter-regulation;
- conserved-variable checks where applicable;
- intervention/event provenance;
- uncertainty propagation;
- replayable simulation history;
- checkpoint/rollback semantics for experiments where appropriate;
- projection consistency across Clinical, Body Exposure and Simulation/Training.

A visual state, clinical state and simulation state may differ in truth class, but they must remain synchronized to the same underlying temporal context.

The goal is not “everything updates at once”. The goal is **everything updates in the correct biological order, at the correct modeled timescale, with explicit concurrent processes and explicit compensation**.
