# Invictus Human Reality Canonical Inheritance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the approved Invictus Human Reality Principle discoverable and binding from Panaceamed's canonical root authorities, future-agent contracts, and governance risk model without changing patient/runtime behavior yet.

**Architecture:** This plan implements only Program A from the approved spec: canonical inheritance. It adds a repository contract test first, then updates the minimum authoritative documents so every future model is told to imagine beyond current capability while preserving epistemic truth, human agency, shared-state continuity, validation, and future-model absorbability. It does not yet implement adaptive-resolution runtime, Human Reality Protocol, model adversaries, meaning-policy code, or other later programs.

**Tech Stack:** Markdown architecture/governance docs, YAML governance registry, TypeScript `.mts` repository contract gate, existing `npm run uji` discovery.

**Spec:** `docs/superpowers/specs/2026-09-28-invictus-human-reality-principle-design.md`

## Global Constraints

- Imagination may exceed current model, sensor and compute capability; patient truth may not.
- Preserve one canonical human/patient-state architecture; do not create a parallel digital twin or parallel truth store.
- Speculative outputs must remain distinct from observed, imported, clinician-verified, derived, simulated, counterfactual, reference, stale, unknown and unsupported state.
- Human agency, consent, purpose limitation, provenance, uncertainty and validation remain mandatory.
- Horizontal expansion is allowed only when it compounds the same Human Reality model and meaning of human life.
- Vertical expansion must stop at the deepest scientifically supportable level and expose gaps rather than fabricate bridges.
- Existing validated capabilities, tests and authority ordering must be preserved.
- This plan changes architecture/governance contracts only; no production clinical/runtime behavior is authorized by this plan.

## Review Focus

1. A future agent reading only root authority files must discover the Invictus principle and the approved spec path rather than relying on chat history.
2. Wording must encourage maximal future imagination without implying speculative state may become patient truth.
3. New Human Reality language must remain compatible with the existing Canonical Patient State / Physiological State Engine separation rather than creating a third authoritative patient-state store.
4. Human meaning and user-authored goals must not become permission for the system to infer or choose values for the user.
5. Governance must explicitly track speculative-truth leakage and future-model/vendor lock-in as architectural risks without weakening existing clinical-overclaim safeguards.
