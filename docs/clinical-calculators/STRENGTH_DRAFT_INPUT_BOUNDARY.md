# Strength log draft input boundary

The strength form now keeps raw strings until every started set has both repetitions and load. Completely untouched rows remain unused; partially filled or invalid rows suppress session volume/1RM previews and prevent saving instead of being silently discarded. Explicit zero remains visible and is rejected by the existing positive repetitions/positive load rule, rather than disappearing into an inferred blank value.

The existing `setSah` rule remains authoritative: whole repetitions 1–100 and finite load above zero through 1,000 kg. These existing limits are technical input bounds, not clinical safety thresholds. Decimal loads accepted by that rule remain accepted; there is no new rounding/clamping. Session date/name validation, stored-session integrity rules, volume formula and Epley formula are unchanged. Volume is sum(repetitions × external load), not measured physiological work; 1RM remains an estimate with the existing above-ten-repetition warning and prohibition on using it as a load to attempt.

`strength-drafts.mts` checks missing/invalid/explicit-zero values, partial rows and a paired property grid across all 100 allowed repetition counts and five valid loads. `strength-draft-smoke.mjs` exercises the actual built mobile form, synthetic data and the existing client cache. The previous built form demonstrably hides an entered zero (`'' !== '0'`). The new fixture requires a partial second set to block save/preview, rejects invalid bounds, and saves only the one complete 5 × 100 kg set (500 kg volume); no phantom blank sets are stored.

This repairs draft input handling only. It does not change the existing global strength-log cache, establish account/tenant separation for that cache, validate biomechanical accuracy or authorize a training prescription. Cache ownership/privacy remains separate work. Clinical reviewer identity, credentials, reviewed version, date and signature are unassigned; clinically_reviewed=false.
