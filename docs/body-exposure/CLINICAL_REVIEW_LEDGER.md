# Clinical review of Body Exposure structures

A structure is **clinically reviewed** only when all of these hold. Nothing in the app, the pipeline or an AI agent can satisfy them by itself.

1. A qualified reviewer inspected that structure in the doctor workspace (`/#/doctor-review/body`, doctor or owner accounts only) and created a review record.
2. The record's decision is `confirmed` and every required check is ticked. The required checks depend on the method (a machine-segmented bone also needs "machine segmentation checked against the images").
3. The record names the **exact asset version** (`panacea_version` plus the mesh vertex and triangle counts). If the geometry changes, the old record stops applying.
4. The reviewer's identifier is in `bodyexposure/manifest/clinical_review_authorizations.json`, which only the repository owner edits, with qualification evidence kept outside the repository. The list is empty today.
5. The record was added to `bodyexposure/manifest/clinical_reviews.json` by pull request.

The rule lives in one place, `src/domains/body-exposure/engine/structureReview.ts` (`recordApproves`). The page, the tests (`scripts/qa/structure-review*.test.mjs`) and the ledger check all use it, so a hand-edited "reviewed" flag without an approving record fails CI.

Data: `public/bodyexposure/<body>.review.json` (one row per structure: ID, name, side, system, accuracy status, method, asset version, source), regenerated by `bodyexposure/pipeline/publish_review_registry.py`. The page loads one body at a time. It never writes anything: the record is shown, copied or downloaded, and a preview states whether it would count.

Status today: 0 of 6,295 structures are clinically reviewed.
