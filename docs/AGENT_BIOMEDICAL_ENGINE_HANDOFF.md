# Panacea Biomedical Technology Engine — Agent Handoff

This is the implementation contract for the next visual/coding agents. Do not restart the architecture from scratch. Extend the scaffold already committed in:

- `src/lib/biomedicalEngineBlueprint.ts`
- `src/lib/biomedicalEvidence.ts`
- `src/pages/bodyhub/BiomedicalEngineLab.tsx`
- existing `src/pages/bodyhub/GenomicsLab.tsx`
- existing `src/pages/bodyhub/CellLab.tsx`
- existing `src/components/Pathway3D.tsx`
- existing radiology/DICOM code
- existing `src/components/Body3D.tsx`
- existing longevity and mental-health modules

## Product mission

Create an end-to-end biomedical technology operating layer that can connect measured human data across scales:

`person → organ → tissue → cell → pathway → protein → gene/variant → sequence/read`

and across time:

`baseline → measurement → evidence update → reviewed interpretation → follow-up`

The product should feel like a 2026 precision-medicine research/decision-support engine, not a collection of unrelated calculators.

## Mandatory truth boundary

The engine may:

- ingest and visualize human sequencing outputs;
- organize known-variant evidence;
- show inherited/somatic disease mechanisms;
- connect variants to proteins, pathways, cells and organs;
- visualize single-cell/multi-omics datasets;
- display measured electrophysiology and physiologic signals;
- reconstruct 3D anatomy from imaging/segmentation data;
- organize published target/therapy evidence;
- support human-reviewed translational R&D notebooks and validation logs.

The engine must NOT claim that it:

- autonomously determines pathogenicity for previously unseen variants;
- autonomously chooses treatment;
- simulates an entire human brain neuron-by-neuron at biochemical fidelity;
- measures “reverse aging” as a validated biological fact;
- autonomously invents or manufactures a drug, vaccine, serum or gene-editing therapy;
- provides executable wet-lab instructions for therapeutic genome editing.

The platform can be ambitious without lying about what has actually been validated.

# 1. Oxford Nanopore / sequencing pipeline

## Data contract

Support progressive import adapters for:

1. `POD5` — raw Oxford Nanopore signal provenance.
2. `FASTQ / FASTQ.GZ` — basecalled reads and Phred quality.
3. `BAM / CRAM` (+ index) — aligned and/or modified-base output generated by a validated external pipeline.
4. `VCF / BCF` — detected sequence variants.
5. FHIR Genomics Reporting objects for interoperable report output.

Do not perform browser-side raw basecalling simply to say it exists. If basecalling/alignment is not genuinely implemented, show an adapter state such as `external-pipeline-required`.

## First production visualizations

- read-length distribution;
- Phred-Q distribution;
- N50;
- coverage track when aligned data exists;
- allele balance / VAF for imported variants;
- chromosome → gene → transcript → variant drill-down;
- variant → protein → pathway → cell → organ linkage;
- germline vs somatic provenance;
- sample/specimen/timestamp/version provenance.

### Existing transparent formulas

`p(error) = 10^(-Q/10)`

`VAF = n_alt / (n_ref + n_alt)`

`N50 = L such that at least 50% of total read/contig length lies in reads/contigs with length >= L`

Do not invent clinical cutoffs around these metrics.

# 2. Hereditary / congenital disease workspace

Build disease dossiers that can connect genotype, mechanism, phenotype, testing and longitudinal outcome for examples including:

- hemoglobinopathies / thalassemias;
- G6PD deficiency and other hereditary red-cell disorders;
- inherited marrow/blood disorders;
- hereditary cancer syndromes;
- congenital metabolic disorders;
- hereditary forms of rickets;
- selected neurodevelopmental genetic syndromes.

Important: autism spectrum disorder is genetically heterogeneous and must not be represented as one gene, one mutation or one editable target. Likewise, “rickets” is a phenotype with nutritional/acquired and hereditary causes; keep cause-specific models distinct.

Each disease card should expose:

- inheritance model;
- known genes/variants only when sourced;
- molecular consequence;
- affected cell/tissue/organ;
- phenotype ontology terms;
- accepted testing modalities;
- evidence-linked treatment context;
- uncertainty and missing-data panel.

# 3. Precision hematology & oncology

Unify existing variant/pathway work with:

- hematopoietic lineage visualization;
- marrow/blood morphology layers;
- clonal timeline visualization;
- somatic vs germline distinction;
- mutation → pathway → phenotype → therapy-evidence graph;

# 4. Single-cell and multi-omics

Build adapters around standard annotated single-cell data rather than inventing synthetic clinical results.

Minimum visualization stack:

- cell clusters;
- cell-type labels;
- gene-expression heatmap;
- pathway activity overlays;
- lineage/trajectory display clearly labeled as inference;
- spatial tissue coordinates when supplied;
- cross-link cluster → cell 3D → pathway → organ atlas.

Suggested interchange target: AnnData/H5AD-compatible structures. Keep raw counts, normalized values, annotations and model-derived embeddings as different provenance classes.

# 5. Radiology → 3D digital anatomy

Extend the existing DICOM work into a strict provenance pipeline:

`source slices → optional validated segmentation → DICOM SEG / segment object → 3D surface → Body Explorer context`

Required UX:

- axial/coronal/sagittal synchronized viewers;
- window/level where modality-appropriate;
- segmentation list;
- opacity and isolate controls;
- 3D mesh reconstruction;
- measurement/provenance panel;
- side-by-side educational reference anatomy.

Never visually merge an algorithmic segmentation with a radiologist-verified finding without labeling the distinction.

# 6. Neuro / pathway / bioelectric engine

Do NOT try to fake a complete neuron-by-neuron whole-brain biochemical simulation.

Instead implement a multiscale inspectable hierarchy:

`brain region → cell class → representative neuron/cell → receptor/channel → signaling pathway → measured signal`

Connect existing pathway concepts such as RAS–MAPK, PI3K–AKT, JAK–STAT and other validated pathways to cell/region context.

Measured-signal adapters may include:

- EEG;
- ECG;
- EMG;
- other physiologic waveforms where a real data source exists.

Visual rules:

- measured signal = solid/primary trace;
- processed feature = secondary trace;
- model inference = dashed/clearly labeled;
- educational mechanism = separate 3D layer.

Suggested signal-derived calculations should remain transparent (for example frequency-domain power when genuinely implemented) and must carry method/version metadata.

# 7. Translational R&D workspace

This is the safe, useful replacement for the phrase “make a drug/vaccine/serum automatically.”

Build a workspace that organizes:

- disease mechanism;
- target evidence;
- pathway position;
- tissue/cell expression context;
- approved and investigational intervention evidence;
- assay results;
- computational simulations;
- human decisions;
- preclinical/clinical validation status;
- failure reasons and negative results.

For CRISPR / genome-editing concepts, the product can display:

- published therapeutic target context;
- known variant/disease linkage;
- conceptual edit class;
- evidence and safety-review checklist;
- connection to existing educational sequence tools.

It must NOT output executable therapeutic wet-lab protocols or present in-browser guide scoring as genome-wide safety validation.

# 8. Longitudinal health / longevity / mental state

Connect currently separated modules into one timeline.

Recommended model:

`raw observation → validated derived metric → trend → contextual factor → reviewed interpretation`

Examples:

- laboratory biomarkers;
- exercise/VO2/functional metrics;
- sleep/recovery;
- nutrition/activity;
- mental-state screening trends;
- medications/clinical events;
- validated biological-age/risk equations already present in the repository.

Never label a lower PhenoAge/risk score as proof of reverse aging. Show score change, uncertainty and contributing biomarkers.

# 9. Evidence engine

Extend `src/lib/biomedicalEvidence.ts`; do not create a second hidden scoring engine.

Current utilities:

- Phred error probability;
- VAF;
- N50;
- z-score;
- generic Bayesian likelihood-ratio aggregation;
- explicitly exploratory weighted normalized-signal index.

Bayesian relation:

`posterior odds = prior odds × product(LR_i)`

or in log form:

`log posterior odds = log prior odds + sum(log LR_i)`

Only use likelihood ratios that come from a validated source. Do not generate fake LRs from model confidence.

# 10. Interoperability

Target FHIR Genomics Reporting for structured genomic reports. Keep:

- report metadata;
- study/analysis metadata;
- specimen;
- genomic findings;
- genomic implications;
- recommendations/tasks;
- source/version information.

FHIR data is an interoperability representation, not evidence that the interpretation itself is clinically correct.

Also preserve DICOM-native provenance for imaging. Add OMOP mapping only as a separate mapping layer when the data dictionary is explicit.

# 11. Astra / ChatGPT 6 visual mission

Astra should focus on multiscale visual coherence:

## Whole-body scale

- select organ/system;
- zoom through tissue → cell → organelle → pathway → protein/gene;
- animated but medically meaningful transitions;
- translucent layer peeling;
- direct structure labels;
- provenance badge always visible.

## Genomics scale

- chromosome helix/ideogram → gene locus → variant;
- variant pulses into protein structure/domain only where a valid model/data link exists;
- pathway nodes change state from imported evidence, not decorative random animation.

## Oncology/hematology

- marrow → lineage → blood cell → molecular pathway;
- clone timeline visualization;
- mutation/pathway graph linked to body sites.

## Single-cell

- cluster cloud → selected cell population → representative cell 3D → molecular pathway;
- distinguish actual dataset embeddings from illustrative 3D arrangement.

## Radiology

- scan slice → segmentation volume → 3D anatomy transition;
- side-by-side source image and reconstruction.

## Neuro

- brain region → cell class → neuron/cell illustration → membrane channels/pathway → measured signal trace.

Avoid sci-fi animation that implies measurements the system does not possess.

# 14. Acceptance criteria

The next implementation is not complete until:

1. A user can identify what data are real measurements versus model-derived versus educational.
2. Every result has provenance.
3. ONT output adapters do not imply basecalling/alignment when none occurred.
4. Known variants can link across gene → pathway → cell → organ.
5. Single-cell data can link cluster → cell state → pathway.
6. DICOM source slices remain inspectable alongside any 3D reconstruction.
7. Longitudinal mental/wellness/longevity data share a coherent timeline.
8. Research outputs cannot silently become clinical recommendations.
9. No therapy-development screen outputs executable wet-lab instructions.
10. The UI works on mobile and remains performant with progressive loading.

## Reference standards / ecosystems

- Oxford Nanopore Technologies output model: POD5 raw signal, FASTQ sequence/quality, BAM when alignment or modified-base calling is used.
- HL7 FHIR Genomics Reporting Implementation Guide v3.0.0 (STU3): genomic report/study/findings/implications and computable reporting structure.
- DICOM segmentation objects for imaging segmentation exchange and provenance.
- AnnData/H5AD ecosystem for annotated single-cell data interchange.

This document is an engineering/product contract, not a clinical protocol.
